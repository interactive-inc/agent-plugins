# 顧客向け文書サイトのページ構造

必要なページだけを選ぶ。製品名、role、業務用語、brandは対象リポジトリの正本に従い、この例を固定値として使わない。

## index.html

ハブページ。ナビゲーションのみ。

構造:

- ヒーロー: 製品名、文書の種別、製品説明（1〜2文）
- OVERVIEW セクション: ドキュメントの目的（顧客が何を読むかを案内する1段落）
- CONTENTS セクション: 各ページへの正方形カード（grid 2列、sm:grid-cols-2）。各カードに番号、ページ名、1行の説明
- フッター: 著作権／製品名

## vision.html

01 / VISION。

- 自由文の概要（製品が何を目指すか）
- 「ビジョン」(h2): 1段落で複数施設を運営する〜のような短いステートメント
- 「解決する問題」(h2): 箇条書き4〜5点。元情報は `index.md` の同セクション
- 「対象」(h2): 1段落でターゲット顧客
- 「運用の原則」(h2): h3 ＋ 段落の4ブロック程度。技術ジャーゴンは平易に書き換え
- 「対象範囲」(h2): 範囲外の領域を箇条書き。「やらないこと」と書かない

## personas.html

02 / PERSONAS、タイトル「ご利用の方々」。

役割ごとに同じ構造を繰り返す。

- h2: 役割名
- h3「この役割の仕事」: 1段落
- h3「従来の状況」: 箇条書き3項目程度
- h3「製品で実現できること」: 1段落

## features.html

03 / FEATURES、タイトル「機能一覧」。

- 冒頭に1段落
- 目次ナビゲーション（rounded-2xl border カード内に grid）。各セクションへのアンカーリンク
- 正本に定義された役割別 h2 セクションと、全役割共通セクション
- 各機能は `<article id="{slug}" class="rounded-2xl border border-line p-6">` のカード
- カード右上に slug をモノスペースで小さく
- 「主な機能」見出しの下に箇条書き4〜7項目
- やむをえない補足は短い1行に
- 末尾は前後ナビ

## business-flow.html

04 / FLOW、タイトル「業務フロー」（必要時のみ）。

- 冒頭に1段落
- 「登場人物」(h2): 箇条書きで役割と役回り
- 「年間サイクル」(h2): 番号付きでなくカード（rounded-2xl border p-5）を縦に並べる。各カードに時期（font-heading text-xs tracking-widest text-brand-500）、見出し、説明
- 業務ロジックの要点を h2 で複数

## roadmap.html

05 / ROADMAP、タイトル「ロードマップ」。

- 冒頭に1段落
- フェーズごとに `<section><div class="rounded-2xl border border-line p-6">` で囲む
  - 日付（font-heading text-xs tracking-widest text-brand-500）
  - h2 でフェーズ名
  - 目的の段落
  - 「含む機能のハイライト」「主な追加機能」など h3 ＋ 箇条書き
  - 内部issueの「残課題」をそのまま載せず、公開済みの今後の対応と現在の対象範囲を分ける

## glossary.html

06 / GLOSSARY、タイトル「用語集」。

- 冒頭に1段落（「初めてご覧になる方向け」のリファレンス案内）
- 対象製品の業界、業務、製品固有語などのカテゴリ別 h2
- `<dl><div><dt>用語</dt><dd>解説</dd></div></dl>` の繰り返し
- 実装ジャーゴンは載せない
