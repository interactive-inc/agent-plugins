# React の設計

- 部品は利用者の目的と責務で分ける。表示と業務判断・通信を一つへ詰め込まず、共通部分は既存の部品を組み合わせる。
- 単方向のデータの流れを保ち、表示から計算できる値を状態として重複保存しない。
- 新規のWeb製品は [stack](../../../stack/SKILL.md) のVoid方針に従い、導入版の画面・データ取得・更新の仕組みを使う。既存製品へ別方式を重ねない。
- 状態を分けて表現する。読み込み中、データあり、空、失敗と再試行を区別する。
- 複雑な状態の遷移は [状態の表現](state-modeling.md) で規則を明示し、画面から独立して試験できるようにする。
- 部品の試験・表示例は製品の既存の仕組みにそろえ、同じ状態や通信の定義を重複させない。
- React Query + Hono RPC を採用済みの製品は [data-fetching](data-fetching.md) を使う。新規製品の必須条件にはしない。
- 書き方と副作用の扱いは [実装規約](../code/react.md) に従う。
