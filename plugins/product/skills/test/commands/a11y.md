# a11y — アクセシビリティ検証

`/product:test a11y`は入力に応じて、codeの静的reviewまたはURLのruntime検証を行う。

## Modes

- code / path / diff → [wcag-level-a.md](../references/wcag-level-a.md)を基準にWCAG 2.2 Level Aを静的reviewする
- URL → browser操作とaxeを使い、機械検出と手動確認を分ける
- 引数なし → UI差分が解決できればcode mode。対象を解決できない場合だけURLまたはpathを確認する

対象リポジトリがより高いlevelや独自checklistを指定していれば、そちらを優先する。

## Static review

1. default branchとの差分または指定pathからUI fileを特定する
2. semantic structure、accessible name、keyboard操作、focus、form error、status announcement、media / motionを確認する
3. runtimeでしか判定できない項目を推測でpassにせず、実行確認へ分ける
4. code、criterion、利用者影響が揃ったfindingだけを報告する

## Runtime review

1. URL、認証方法、対象state、viewportを確定する。入力済みなら再質問しない
2. 対象リポジトリが指定するbrowser手段で実際に操作し、keyboard pathとfocusを確認する
3. axe runnerが利用可能なら実行する。bundled runnerを使う場合、依存が無ければ勝手にinstallせず許可を得る
4. axe violationをDOMと画面で再確認し、false positiveを除く
5. screen reader固有、認知、操作順など自動判定不能な項目をmanual checklistへ分ける

一時dataは`/tmp/product-test/a11y/<run>/`へ置く。対象リポジトリの許可なく`docs/`へreportやscreenshotを生成しない。

## Report

次を分ける。

- confirmed violations: criterion、element / path、reproduction、impact、修正方向
- automated clean: 実行したrule範囲だけ
- manual checks: 人間または補助技術で確認が必要
- excluded / untested: 理由付き

artifactの保存・uploadが禁止されている場合は確認後に削除し、URL、account type、viewport、操作、結果を文章で残す。
