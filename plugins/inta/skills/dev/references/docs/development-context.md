# 対話と実装から得た理解を残す

- `.docs/index.md` は全体の目的と現在の判断への入口。背景・決定と理由・未解決の問いは対応する既存文書へ残す。
- `AGENTS.md` には今後も繰り返し必要な短い規約と参照先を残す。会話の全文、今回だけの手順、実装から分かる一覧を積み上げない。
- 目的を見て必要な部分を作り、試験と実表示から得た発見を全体の理解へ戻す。関係する記述の整理は開発に含める。
- 追記前に同じ話の正本を探す。古い説明は更新・統合し、同じ規則を複製しない。決定の理由や人の記述は保護する。
- 既存の目的・優先順位・業務要件を変えるときは対話する。現在の実装と違うという理由だけで、その方針を消さない。
- 文書の種類と書式は既存の [入口](index.md)・[文章規約](writing-rules.md) に従う。必要なものだけ作り、形式を満たすための空文書を増やさない。
