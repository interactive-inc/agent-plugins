# 製品の PR 方針 — 設定ひな形

以下は架空の初期案。対象製品の既存規約を読み、必要な項目を決めてから正本へ保存する。空欄や未合意の状態では自動マージを有効にしない。

```md
# PR 方針

## 対象と許可

- リポジトリ／base：未設定
- 自動マージ：未合意
- 対象：この製品の開発依頼で作成・更新する PR。外部投稿・bot の PR は別途指定
- 今回の依頼で「PR まで」等の上限がある場合はそれを優先する
- マージ方式：未設定
- 実行：dev が検査完了後にマージ。待機中の GitHub 自動マージは未導入

## レーン

| ラベル | 判断 | マージ条件 |
| --- | --- | --- |
| lane:auto | 下記の要確認条件がなく、共有する論点もない | 必要な検査の成功。人のレビュー不要 |
| lane:share | メンバーに共有したい背景・発見・問題提起がある。事前の意思決定は不要 | PR に論点を残し、通常と同じ条件でマージ |
| lane:approval | 下記に該当、または影響不明 | 必要な人の判断を残し、検査・GitHub のマージ条件を満たす |

## 要確認の境界

- データ：スキーマ・migration・backfill、既存データの一括変更・削除、互換性・負荷に影響する変更
- 事業：請求・権限・公開・契約・不可逆な状態遷移など。製品固有の操作を追記する
- 技術：認証境界、破壊的な公開 API 変更、大きい障害範囲など、担当者だけで判断できないもの
- 判断する人／対象：未設定。データ・事業・技術で必要な相手を決める
- 判断の記録：PR の確認対象 head SHA と、誰が何を了承したか。追加変更は再判定する

## 検証と共有

- 必須チェック／CI 外の検証：未設定。チェック名と成功条件を列挙する
- GitHub 保護・CODEOWNERS：現行規則を確認して記載。迂回しない
- 共有先：PR 本文。追加の通知は依頼済みの経路がある場合だけ
- 再判定：追加 push・base 変更・先行マージで影響が変わるたびに実施
- 保留：未分類、複数レーン、未解決の判断・変更要求、検査未確認、競合、権限不足
```
