# UI の試験と表示例

Storybook / MSW を採用済みの製品で、表示状態と通信の配線を確かめるときに読む。具体的な API は導入版の公式資料と既存設定へ合わせる。

## 状態とデータ

- 表示だけの部品は props、通信を含む部品は実 hook と MSW を使う。正常・空・失敗・権限制約を、製品が実際に取り得る組合せで表す。
- 合計・割合・日付・権限は既存の定義や計算から作る。fixture は架空データとし、個人情報や実在の本番記録を写さない。
- story と試験で通信ハンドラを共有する。ブラウザとテスト runtime の URL 解決をそれぞれ確認し、未定義リクエストを実サービスへ流さない。
- QueryClient は表示例間で分離し、同じ mount の再描画では維持する。毎 render の再生成による再取得ループを防ぐ。

## 配線の確認

MSW の登録方法、decorator の合成、DOM runtime の origin は導入版で確認する。型エラーを隠すために component の契約を偽らない。モック・ブラウザ用 worker を本番へ含めない。

ビルド成功だけで表示確認としない。実際に story を開き、モックのデータ、空表示、失敗状態が意図どおり描画されることを確かめる。

全件 smoke がある場合は実際の story 一覧から列挙し、HTTP 失敗・実行時例外・エラー画面・描画完了を判定する。閉じた dialog など正当に空になる状態を一律失敗にしない。除外には理由を持たせ、解消済み・削除済みの除外も検出する。

全件の到達確認と、金額・権限・グラフなど表示内容の正しさは別に検証する。大規模な全件実行は CI の時間と負荷に合わせて分割する。
