# コードレビュー

対象の差分と、その利用者・呼び出し元・設定・試験を読み、実害のある問題を探す。対象が未指定なら現在の変更と default branch の比較を使い、比較基点と未確認範囲を明示する。

## 見るところ

- 入力から出力までの経路と、変更が届く利用者・データ・権限の範囲。
- 状態の作成・更新・削除、期限、失敗途中、再試行、並行実行。変更行の外に残る状態や別の利用箇所も追う。
- API・DB・キャッシュ・設定・既存データとの互換性。性能問題はデータ量と呼び出し回数で確かめる。
- 責務と依存は [設計規約](../design/architecture.md)、React Query + Hono RPC の変更は [データ取得](../design/data-fetching.md) に照合する。
- 試験が利用者に必要な振る舞いを守るか。回帰試験は可能なら修正前に失敗することを確かめる。

PR は説明と実際の差分を照合する。委託された差分も自分で読み、報告された検証・前提の訂正・未対応の判断を裏付ける。マージや rebase 後は、変更対象の移動と依存の更新も確認する。

## 指摘

根拠のある問題を影響の大きい順に、場所・発生条件・利用者への影響・修正方針とともに返す。検索の一致、好み、理論上だけの懸念を不具合として並べない。未解決の仕様判断と未検証は、確定した問題と分ける。問題が見つからなければ、その結果と検証の限界を短く伝える。

レビュー依頼だけで実装・Issue・PR コメントを変更しない。書き込みを依頼された場合は [Issue・PR](issue-pr.md) と [GitHub 運用](github.md) に従う。
