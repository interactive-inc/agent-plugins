# レビューと PR レーン

変更の問題は既存のレビュアーに確認し、人の判断が必要かは [PR レーン](references/pr-lanes.md) で分類する。コードの問題・検証不足と、事業や移行の意思決定を分ける。

| 入力 | 進め方 |
| --- | --- |
| PR・パス・引数なし | 下記の既存レビューを呼び、結果と実際の影響からレーン・根拠・共有する論点・人に確認する点をまとめる |
| `classify <PR・差分>` | 最新の差分・製品方針・検証結果からレーンだけ判定する。全コードレビューは追加しない |
| `lanes`・レーンの設定 | 製品固有の条件・必要な検査・判断する人・マージ許可を設定する。手順とひな形は上の正本を使う |

通常のレビューと `classify` は読み取り専用。ラベル・本文の更新は依頼された範囲だけ行い、レビューを呼ぶこと自体をマージの許可とみなさない。`dev` からの分類は開発の一部として扱い、更新・マージの許可は元の依頼と製品の設定を引き継ぐ。

通常・共有は人のレビューを待たず、合意済みの検査後に進める。要確認では必要な判断だけを人に渡す。AI レビューの成功を人の了承として扱わない。全コードの AI レビューも毎回の必須条件にはせず、明示された依頼・製品方針・具体的な必要性に従う。

## 既存のレビュー

利用中のクライアントに応じて、依頼された対象・引数・観点を既存のレビューへ渡す。

- Claude Code: 組み込みの `code-review` スキルを呼び出す。
- Codex: 標準の `review`（`/review`）を使う。セッションから直接呼べない場合は、対象リポジトリで `codex review --help` を確認し、同じ標準レビュアーを `codex review` から呼ぶ。対象指定がなければ `--uncommitted` を使う。

コードレビューの基準・進め方・出力は呼び出し先に従い、その結果にレーン判断を添える。修正やコメント投稿は依頼された場合だけ渡す。呼び出せない場合は理由と必要な操作を伝え、独自のコードレビューで代替しない。レーン判定だけ行えた場合もコードレビュー完了とは報告しない。
