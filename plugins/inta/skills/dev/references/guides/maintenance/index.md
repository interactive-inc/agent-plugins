# 挙動を保つ手入れ

人間が独立して依頼したコード・文書・構成の整理。開発に伴う整理は `dev` に含め、毎回別工程にしない。

依頼の対象がコード・開発文書・README のどれかを判断する。各対象の規約は [scopes.md](scopes.md)。自然文から対象が明確ならその範囲で進め、不明な場合だけ確認する。

作業前に Git の状態、関連する Issue・PR、規約と実装を確認する。無関係な変更・生成物・保護された記述を守り、確認できた問題から必要な差分だけ直す。

挙動や公開範囲を変える判断を手入れに紛れ込ませない。意図した要件と現状の説明を区別し、修正方向が決まらないものは対話へ戻す。変更した経路の検証とリンク確認を行い、何を整理したか・何が未確認かを返す。
