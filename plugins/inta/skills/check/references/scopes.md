# 点検範囲

## changed

引数なしは現在の変更と直接影響する範囲を点検する。差分がなければ既存の課題や履歴から候補を最大10件に絞り、選んだ範囲を示す。環境、文書、コード、仕様の接続から関係する観点だけを使い、無関係な全試験を起動しない。

## full

`full` を明示されたときだけ、対象製品全体を点検する。保護領域・生成物・既知の例外を確認し、標準の品質検査と利用可能な専用 checker を使う。仕様の追跡には [trace](../commands/trace.md) の `all` を使う。検査できない範囲は残す。

## code

変更に必要な試験は [test changed](../../test/commands/changed.md)。加えて、型と I/O 境界、認可、状態・失敗・再試行・並行実行を [レビュー](../../dev/references/tools/review.md) と [設計規約](../../dev/references/design/architecture.md) に照合する。

未使用検出や巨大ファイルの集計は候補探しに使う。削除候補は re-export・動的参照・framework の入口・公開 API まで確認する。行数だけで違反とせず、責務や変更理由の混在を示す。試験の skip・retry・時刻依存も、実際の検出力に影響するか確かめる。

## docs

README・`.docs` の検証可能な主張を、実装・設定・schema・認可と突き合わせる。Feature は独立して受入条件を持つ業務能力、Story は複数能力を通じた利用者の完了条件として粒度を確認する。

文書のリンクは既存 resolver で確認する。未解決・重複・曖昧な参照・入口から到達できない文書を調べるが、循環リンクや古い日付だけを不具合としない。明示された path・Feature ID・領域があればそこへ絞り、修正方向が不明なら未確認とする。

## readme

README と AGENTS.md / CLAUDE.md などの入口に、読者に必要な情報が置かれているか確認する。command・path・設定を実装に照合し、安全に実行できない setup / deploy は未検証とする。重複や終了済みの注意書きは根拠と推奨先を示す。
