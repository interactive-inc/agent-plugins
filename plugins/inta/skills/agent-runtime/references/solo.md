# Solo runtime

`sonnet` と `opus` は起動時の checkout で自ら実装し、必要な場合だけ委譲する軽量なメインプロセス。

## 共通境界

- ブランチを作成・切り替えず、primary checkoutにいてもこの境界は変えない
- Issue / PR / worktree を運用せず、外向き操作は明示依頼時だけ行う
- 同時に取り組む案件は1つだけ。会話で出た別件は `.docs/notes/` に記録し、今の案件が終わってから着手する
- `.docs/` は index / sitemap / architecture / glossary / notes 程度に留め、signals / backlogs などの管理台帳は持たない
- dev server は自分だけが扱い、[dev-server.md](../../dev/references/tools/dev-server.md) に従う
- UI 変更は自分でブラウザ確認し、検証結果を根拠に受け入れる

## 委譲

- worker に渡すのは、影響範囲が広い、コードベース全体の把握が要る、自分のコンテキストを大きく消費する実装だけ
- `opus` は codex が使える環境なら、スコープが確定して少数ファイルで閉じる実装を codex に渡す。最初の委託前に codex CLI と codex 用 Skill の有無を確認し、揃っていなければ自分で書く。些末な一行修正は自分で直す
- 指示は1通で完結させる。確定済みの計画、関連パス、背景と意図に加え、完了の定義と止まって返してよい条件を必ず入れる
- worker には「Issue / PR / worktree は使わない、現在のブランチでコミット止まり」、codex には「ブランチを作成・切り替えない」と明示する
- 思考の指示や思考過程の書き出しを求めない。判断理由が要るなら成果物として短く頼む
- 走行中に追加された指示で委託中の作業に関わるものは、やり直させず実行中の worker へ届ける
- 戻り値は変更ファイル、検証結果、未解決点、確認できなかったこととそのためにどこを見たかに限定する

## 判断主体

- `opus`: 設計、計画、差分評価、受け入れを自分で判断する
- `sonnet`: 判断余地がある設計、委譲、受け入れを advisor にまとめて確認する。事実から一意な調査や局所実装には呼ばない

advisor が利用不能なら黙って代替せず、判断が必要な地点で状況を報告する。

## 自走と停止

入力が要らない工程は止まらず続ける。次の一手を書くだけの要約、「続けますか」、作業を塞がない選択肢の列挙で止まらない。ターンを終える前に最後の段落を確かめ、そう終わりそうならその一手を今やってから終える。

止まって聞くのは、結果を変える選択が未決定、権限が不足、依頼範囲の外へ広げる必要がある、破壊的操作または依頼にない外向き操作の直前の場合だけ。権限の確認で止められた操作は別のコマンドで迂回しない。

数時間に及ぶ作業では、進行表を scratchpad のファイルに持ち、会話が要約された後は記憶ではなく進行表を正にして再開する。進行表はコミットしない。

## 受け入れ

- 受け入れ判定ではマージを止める問題だけを挙げ、1件ごとに file:line、なぜ誤りか、失敗を示す方法を添える。止めるほどではない気づきは報告の「発見」へ回す
- 型チェック・lint・テスト、挙動を変えた場合の `.docs/` 更新、UI 変更の実ブラウザ確認、DB スキーマ変更のローカル適用を満たすまで完了にしない
- UI は空データとデータあり、portal 系の開閉、対象画面への到達、余白・整列・重なりを確認する。視覚の判定は変更前後のスクリーンショットを並べて比べる
- 対象リポジトリのデザイン規約で決まらない見た目は、避けるパターンを具体名で決めてから作る

## 報告

作業の区切りでは「判断待ち」「変更」「発見」の3見出しで締める。短い往復ではこの形式を使わず端的に答える。報告は検証結果で裏づけられる事実だけにし、未検証は未検証と明言する。
